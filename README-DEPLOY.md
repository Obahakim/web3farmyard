# Web3Farmyard v2.0 — Next.js Static Export

## Local Build Steps (run on your computer)

1. Install Node.js 18+ from https://nodejs.org
2. Extract this ZIP to a folder
3. Open terminal in that folder and run:

```bash
npm install
npm run build
```

4. The `out/` folder is generated — this is your website
5. Also copy into the `out/` folder:
   - `api-proxy.php` (copied into `out/` automatically by the build script)
   - `uploads/` folder (ebook PDF)

Database SQL belongs in `supabase/migrations/` and is applied through Supabase, not copied into the static website. The security migration in that folder has already been applied to the connected production project.

## Upload to Hostinger

Upload the ENTIRE contents of `out/` to `public_html/`.
The `.htaccess` file is included automatically in the build.

## Showroom daily snapshot

The Showroom remains a static export. Its TVL, DEX-volume, and NFT-volume rankings read a daily JSON snapshot generated by `refresh-showroom-cache.php`; `showroom-data.php` serves that snapshot to the page. Use Hostinger's cron so the refresh runs beside the cache file; GitHub Actions is possible, but would need SSH credentials and adds an external connection just to run this same command.

### 1. Upload the snapshot files

Build the site and upload the contents of `out/` to Hostinger's `public_html/`. Confirm these files are there:

- `refresh-showroom-cache.php`
- `showroom-data.php`
- `showroom-data.json`

### 2. Find the full server path

In hPanel, open File Manager for the domain and locate `refresh-showroom-cache.php`. Use its full path in the commands below. It usually looks like:

```text
/home/<account>/domains/web3farmyard.com/public_html/refresh-showroom-cache.php
```

Replace `<account>` with the account directory shown by Hostinger; do not enter the angle brackets literally.

### 3. Run the first refresh once

The first run must use `--force`, because the uploaded JSON file may look newly created even though it contains only an empty placeholder. If SSH access is available, connect to the hosting account, confirm PHP and cURL are enabled, then run:

```bash
php -v
php -m | grep -i curl
php /home/<account>/domains/web3farmyard.com/public_html/refresh-showroom-cache.php --force
```

The command should report that the snapshot was refreshed and how many chains were included. If SSH is unavailable, create a temporary cron job with the `--force` command, schedule it to run once soon, then remove that temporary job after it succeeds.

### 4. Create the daily Hostinger cron job

1. In hPanel, open **Websites → Manage** for the domain, then find **Advanced → Cron Jobs**. Menu labels can vary; search hPanel for “Cron Jobs” if needed.
2. Create a cron job with a custom schedule of once per day. For example, `17 3 * * *` runs daily at 03:17 in the server's cron timezone. Choose a quiet hour and check the timezone shown by Hostinger.
3. Set the command to the same PHP command **without** `--force`:

   ```bash
   php /home/<account>/domains/web3farmyard.com/public_html/refresh-showroom-cache.php
   ```

4. Save the job. Keep the command's output or error notifications enabled if hPanel offers them.

Set the first daily run for at least 24 hours after the successful `--force` refresh, then keep it at the same time each day. The script skips a refresh when the last successful snapshot is less than 24 hours old, so a duplicate run will not make another API batch. Do not create a public URL to trigger the refresh; it is intended to run from PHP CLI.

### 5. Verify the snapshot and page

Open `https://www.web3farmyard.com/showroom-data.php`. Confirm the JSON has a recent `updatedAt`, a non-empty `chains` array, and `nftVolume24h` values for chains covered by DeFiLlama. Then open `/showroom/` and test the TVL, DEX-volume, and NFT-volume ranking buttons.

If the timestamp does not update, check the cron's latest output, the PHP cURL extension, the command's absolute path, and that the PHP account can write `showroom-data.json`. Do not make the file world-writable; ask Hostinger support if its ownership or permissions prevent the cron from replacing it.

Each daily refresh makes up to about 408 requests to DeFiLlama (one chain list, one DEX overview, one NFT-volume overview, DEX volume per supported chain, and historical TVL for chains appearing in either top-50 ranking). Requests run in batches of six with a 15-second timeout; with current chain counts, even repeated timeouts should keep the refresh under about 18 minutes. Typical runs should be shorter, subject to Hostinger’s execution limits. If the cron fails, the last successful snapshot remains in place and the page shows its timestamp.

## Hostinger API proxy secrets

After uploading the static export, configure the private PHP secrets file outside `public_html`. Follow [`docs/security/hostinger-api-proxy-setup.md`](docs/security/hostinger-api-proxy-setup.md). Do not copy the private secrets file into `out/` or commit it. The proxy requires the Supabase secret key, rotated Resend key, a new admin password, a session secret, and an unsubscribe secret. The Anthropic key is required only for the AI proxy action.

## What This Generates

- `/` — Homepage
- `/airdrops/` — Airdrop listings  
- `/showroom/` — Top-50 TVL, DEX-volume, and NFT-volume rankings, with 24-hour TVL-change data
- `/showroom/[chain]/` — Individual page for every DeFiLlama-tracked chain (~400 pages)
- `/junkyard/` — Dead projects grid
- `/junkyard/[project]/` — Individual project post-mortems
- `/resources/mobile-farmer/` — Ebook landing page
- `/sitemap.xml` — Auto-generated with all tracked chain pages
- `/robots.txt` — Proper crawl rules

## PageSpeed Expectations
- Desktop: 90-95

- CSS is Tailwind — compiled, cached, tiny
- Fonts: Google Fonts with display=swap (no render-block)
